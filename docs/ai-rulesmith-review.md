# ai-rulesmith teardown

**Read:** v0.4.3 source, 2026-08-23. Unmaintained (last publish 2026-03-01),
so this is a design reference only — not a dependency.

## Model

`AI_RULES.json` is an array of _targets_. Each target names an output adapter
and an `ai_workflow` that lists rule slugs to include:

```json
[
  {
    "target": "claude-code",
    "ai_workflow": {
      "type": "standard",
      "before_start": ["ai-behavior/clarify-dont-assume"],
      "rules": [
        "code-style/small-focused-functions",
        { "slug": "code-style/no-hardcoded-values", "vars": { "x": "y" } }
      ],
      "before_finish": ["testing/never-weaken-tests"]
    }
  }
]
```

Rules are one markdown file per rule, slug `category/rule-name`, gray-matter
frontmatter (`name`, `description`, `category`, `tags`, `vars`).

## Worth taking

| Piece                                                                                  | Why                                                                                                                                                   |
| -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `category/rule-name` slugs, one `.md` each                                             | Flat addressable registry. Same shape as an eslint rule id.                                                                                           |
| 3-layer resolve-by-slug: `.rulesmith/rules/` → `~/.config/rulesmith/rules/` → built-in | First hit wins. A project drops in a same-slug file to replace a rule's body wholesale — that's "we like this rule but our version differs".          |
| `vars` frontmatter + `{{name}}` substitution, with `default` / `required`              | This is eslint rule _options_. My earlier handoff dismissed it as only mattering when shipping to strangers — a team is strangers.                    |
| Generated header: `<!-- Generated by … do not edit -->` plus the source slug list      | Output is traceable and regenerable. Cheap, do it.                                                                                                    |
| Target registry (claude-code / cursor / copilot / codex / windsurf)                    | Adapter is just `{ mainFilePath, stepFilePattern, supportsFileReferences, transformOutput? }`. Trivial to keep the seam even while only Claude ships. |
| `before_start` / `rules` / `before_finish` ordering buckets                            | Cheap way to give generated output a shape instead of a pile.                                                                                         |

## Deliberately not taking

- **`type: "steps"` workflows** — emits `.rulesmith/steps/step-N-*.md` phase files. Procedure, not rule. That's a skill.
- **`llm-client` + `scenario-tester`** — a `test` command that asks an LLM whether a rule "works". Needs an API key, non-deterministic, no.
- **`init` prompt wizard** — a hand-written config file is fine.

## What it does NOT solve — and it's the important half

No `extends`. No disable. No glob scoping.

The config is a flat **include list**: a rule is on because you typed its slug.
There is no shareable base config to inherit and then trim, so the exact
workflow asked for here — _start from a recommended set, switch two off, retune
a third, add one of our own_ — has no representation. Its layered resolution
overrides a rule's **content**, not the **decision to use it**.

Adding `extends` + per-rule `off` on top of this model is the actual work.
Nothing in the package needs to be forked to get there; the file format is
the reusable part.
